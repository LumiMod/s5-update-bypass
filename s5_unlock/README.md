# S5 验签开关工具（macOS）

一键把 Lumix S5 相机 RAM 里的**固件更新验签开关**从 0 改成 1，跳过更新时的签名验证。

> ⚠️ **实验性工具**。开关地址和逻辑来自固件静态分析（已确认），但**是否真机生效尚未验证**。写 RAM 有风险，请先读 [验签开关验证.md](../s5_v29_decrypted/验签开关验证.md) 了解证据链。

## 原理

固件 program 里有一个更新控制块，位于物理地址 0x86318000：

| 偏移 | 用途 |
|---|---|
| +0x08 | 状态 |
| +0x0a | 版本 |
| +0x18 | 位标志 |
| **+0x1a** | **验签开关（0=验签，1=跳过）** |
| +0x1c / +0x1e | 标志 |

更新流程在 0x647048 处读这个 halfword：

    0x647048: ldr   r0, [pc, #0x180]     ; r0 = 0x06318000
    0x64704a: ldrh  r0, [r0, #0x1a]      ; 读开关
    0x64704c: cmp   r0, #1
    0x64704e: beq   #0x647094            ; == 1 → 跳过验签

开关 = 1 时，跳过组件级 SHA-256 比对和 ECDSA P-256 验签。

## 使用

### 前置条件

1. 相机进入**服务模式**：PLAY + AF-ON 同时按住开机
2. USB 线连接 Mac
3. 相机出现在系统里（VID 04DA / PID 2370）

### 图形界面（推荐）

双击 S5Unlock.app，然后：

1. 点「连接相机」
2. 点「读取开关」确认当前是 0x0000
3. 点「一键跳过验签」
4. 读回确认变成 0x0001
5. 触发固件更新，观察是否跳过验签

### 命令行

    python3 s5_unlock_cli.py status    # 读开关
    python3 s5_unlock_cli.py unlock    # 写 1
    python3 s5_unlock_cli.py restore   # 写 0
    python3 s5_unlock_cli.py dump      # 读上下文

## 协议

对应 Windows 版 lumix_ml/usb_link.py：

- 控制传输：bmRequestType=0x40, bRequest=0, wIndex=0/1
- 写管道 EP 0x01，读管道 EP 0x82
- 读 1 KiB：opcode 0x5C，帧 1030 字节
- 写半字：opcode 0x9C，帧 16 字节

## 已知限制

1. **开关是否生效未验证**：静态分析确认了代码逻辑，但真机更新流程可能重新加载 program 镜像，把 RAM 修改覆盖掉。
2. **容器级签名未确认**：开关跳过的是组件级校验；容器 0x220 处的 64 字节签名是否也被跳过，尚未确认。
3. **变砖风险**：写错地址或相机状态不对可能变砖，没有恢复手段。
4. **只写 RAM**：不修改 NAND，重启后恢复原状。

## 下一步验证

1. 服务模式读 0x8631801a，确认是 0x0000
2. 写 0x0001，读回确认
3. 先触发一次**官方签名固件**更新，确认流程正常
4. 构造一个**故意改坏哈希**的更新包，再触发：
   - 被拒绝 → 开关没生效（可能被重载覆盖）
   - 被接受 → 开关生效
